# 人类专用归档

这个目录放**参考侧的具体细节**：哪个文件、哪个函数、第几行、转述的片段、
从哪一次观测反推出了什么。一卡一档，文件名与卡片 id 同名
（`R-2201-001.md` ↔ `provenance/R-2201-001.md`）。

## 为什么要有它

卡片正文过 lint：L-DENY 拦参考的私有符号名，L-BANNED 拦「参考实现」这类
词，L-NARRATIVE 拦日期/轮次/算子名。这些都对 —— 一条经验要能被一个
**没有这份参考**的 campaign 读懂。

但真从参考行为反推出结论的 agent 手上确实握着那些细节。不给它去处，它只有
两条路：

| 路 | 结果 |
|---|---|
| 写进卡片 | 被 lint 拦住 → 改成模糊表述绕过去，细节丢了 |
| 直接丢掉 | 零成本、零报错 → 结论从此不可复核 |

两条都通向「结论不可复核」。而它会选第二条，因为那是免费的。

## 谁能读

**人**。agent 读不到：

- `hwkb query` 只遍历 `ARCH_DIRS` 下的 `*.md`，不扫这个目录
- `hooks/hooks.json` 的 `permissions.deny` 有
  `Read/Grep/Glob(//**/forge-hwkb/references/provenance/**)`

只靠目录布局是不够的 —— 那只保证「不主动递给它」。deny 才保证「它拿不到」。
两样都要：少了布局，`query` 会把归档当卡片吐出来；少了 deny，一次
`Read` 就绕过去了，而这个目录比卡片更危险 —— 卡片至少过 lint。

## 怎么写

没有格式要求，这是给人看的。但至少要能回答：

1. 这个结论是从哪次观测、哪个通道的哪个数来的
2. 参考侧的哪个具体事实支撑它（文件/函数/行号/转述）
3. 换一个参考时，这个结论里哪部分会变、哪部分不会

确实没有参考侧细节（结论纯粹来自公开文档与自家探针）时，就在归档里写这
一句 —— `provenance_archive` 是必填字段，空文件和「没有细节」是两件事，
后者要写出来。
