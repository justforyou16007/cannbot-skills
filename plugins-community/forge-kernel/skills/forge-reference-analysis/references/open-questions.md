# 开放问题：msprof 分辨不了什么

## 为什么要专门写这个

论文 §3.2 对参考分析有一条要求：**仪器分辨不了的，留作显式的开放问题**。

这条要求看起来是退让，实际是质量控制。一个诚实标注的开放问题可以被后续
实验回答；一个伪装成结论的猜测不能 —— 它会被当作既定事实，后面所有依赖
它的决策都建在上面，而且因为它看起来「有数据支撑」，出错时极难定位。

`milestone_validate.py` 的 V2 规则会拒掉给不出 trigger 的决策，
本文件就是用来判断「这个决策到底有没有 trigger」的依据。

---

## 一、分辨不了的清单

### 具体 tile 形状

**为什么不行**：多种划分可以产生相同的搬运总量与核数。msprof 给的是
总量级，不是划分方式。

**能做什么**：
- 把能确定的写进去：核数（`Block Dim`）、搬运量级（MTE2 占比 + 活跃带宽）
- tile 形状本身列为开放问题
- 用自己的实现做对照：换几个 tile 形状，看哪个的占比分布最接近参考

### Buffer 的精确布局与 bank 分配

**部分可观测 —— 这一条在早期版本里写错过，特此更正。**

读不出来的是**具体布局方案**：哪个张量放在 UB 的哪个偏移、怎么 padding。

**读得出来的是布局有没有造成问题**：`ResourceConflictRatio.csv` 明确区分

- `aiv_vec_bank_cflt_ratio`（<3%）—— 操作数读写指针地址不合理，撞同一 bank
- `aiv_vec_bankgroup_cflt_ratio`（<3%）—— block stride 不合理，落入同一 bank group

这两者的改法不同（调地址分配/加 padding vs 调 stride），所以能区分它们
本身就有价值。

**能做什么**：把「参考的布局没有 bank 冲突」写成可验证的架构约束
（有 trigger，有停顿锚点）；把「参考具体怎么摆的」留作开放问题。

### double buffer 的具体深度

**为什么不行**：重叠的**效果**可观测（各段占比的饱和程度），
重叠的**深度**不可观测。

**能做什么**：把「存在搬运与计算的重叠」写成架构决策（它有 trigger），
把深度留给战术层去扫。这个划分本身就符合两层划分的原则。

### 同步原语的具体用法

**为什么不行**：无对应字段。

**能做什么**：不写进架构决策。同步属战术层，由实现者按目标架构的机制
（DAV_2201 的 set/wait 或 DAV_3510 的 BufferID）自行选择。

### 重算与存储的边界位置

**为什么不行**：只能从搬运量的变化间接感知，而搬运量的变化有多种成因。

**能做什么**：设计对照实验 —— 做一版偏重算的、一版偏存储的，
比各自的占比分布与参考的接近程度。这是开放问题中最值得花实验预算去
回答的一个，因为它属于 M0，定错了后面全要重来。

## 二、DAV_3510 特有的分辨困难

### CV 直通通路让搬运量推断失准

DAV_3510 新增了 L0C→UB、UB→L1 直通，**部分数据流动不出现在 MTE2/MTE3 里**。

所以在这一代上，「MTE2 占比低」有两种可能：
1. 数据复用做得好
2. 走了直通通路，流动没被计入

两者的后续优化方向完全相反。区分不开时必须列为开放问题，
不要默认是第一种。

可尝试的交叉验证：看 `aic_fixpipe_ratio`、`aic_mte1_ratio` 是否异常活跃。

## 三、可以考虑的替代探针

当某个问题足够重要（通常是 M0 层的决策）时，可以设计针对性实验来逼近答案：

| 想知道 | 可以怎么探 |
|---|---|
| 参考的 tile 形状 | 自己实现几个候选形状，比占比分布的接近度 |
| 某个机制是否存在 | 做一个**故意破坏**该机制的版本，看占比是否朝预期方向变化 |
| 某项开销的量级 | 删掉该操作（即使结果变错），测时间差 —— 论文称之为给手段定价 |
| 是否已达硬件上限 | 用 `aic_cube_fops` 折算利用率，或看活跃带宽是否贴近 HBM 上限 |

第三项「删掉它看差多少」是外层循环的常用手段：它不产出可用的 kernel，
但能把「这条路还有多少空间」量化出来，用来决定要不要继续在这个方向上投入。

> 论文在 DSA 稀疏注意力的案例里正是这么做的：单独去掉输出写回这一项，
> 测得 6% 的差距，据此判断瓶颈在 kernel 的边界上，进而重开了 M0 的
> 第一个决策。

## 四、写进 milestone 的格式

开放问题不是免责声明，它应当是**可被回答的**。写的时候带上三件事：

```json
{
  "id": "Q1",
  "question": "参考的 reduce 轴是整行常驻还是行内二次切分？",
  "why_unresolvable": "两种划分在当前 shape 下产生的搬运总量相同，MTE2 占比无法区分",
  "proposed_probe": "实现两个版本，比 aiv_mte2_ratio 与参考 61.2 的接近度",
  "blocks": ["D0.1"]
}
```

`blocks` 字段指出哪些决策在等这个答案。如果一个开放问题谁也不挡，
那它多半不值得占用实验预算。
